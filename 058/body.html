{{fig_counts}}

How a PR reaches dev now. dev takes PRs through GitHub's merge queue, which builds up to five at a time, together, on top of dev, and merges them only if all are green. Two checks are required, Fast checks and Static checks, and one approving review from a code owner: every file's owner is the hazel-core team (Cyrus Omar, Alexander Bandukwala, Andrew Blinn, Thomas Porter, Matt Keenan and Matthew Hammer), and an author cannot approve their own PR. A PR's CI takes about 17 to 21 minutes (hazelgrove/hazel#2828's last two runs). Because the queue tests each group on the latest dev, a PR that is behind dev but merges cleanly needs no update first; one that conflicts must be resolved by hand.

How this was put together

Gathered on 2026-11-19 between 07:15 and 07:35 MST. GitHub's view of each of Matthew Hammer's open PRs (gh pr list --author matthewhammer, then gh pr view for its size, draft state, base, head, checks at the head, reviews and comments), with each PR's description, reviews and comments read for what it needs. Each PR into dev was fetched (refs/pull/N/head) and merged into dev at {{dev_commit}} with git merge-tree --write-tree, which merges without a checkout and names the files that conflict; the ready PRs were then merged one after another, in the queue's order, the same way, each on the result of the last, and all merged cleanly. Pairs of candidates were merged the same way to find the conflicts between them. dev's rules are its ruleset and branch protection, read from GitHub's API, and its .github/CODEOWNERS. The last column of the tables counts non-merge commits on dev since 2025-11-01 that touch the PR's source files, by author, for the members of hazel-core other than Matthew. Nothing was built or tested for this report, and no PR was changed. The driver is 058/drivers/prep058.py; its output, 058/data/prs.json, and the tiers, 058/data/tiers.json, are with the report.
