An Open Font for Hazel’s Interface

Hazel’s interface font was Helvetica Neue, a commercial typeface, from a copy Hazel served with every build, with no license for it on record. Since hazelgrove/hazel#2837, Hazel ships no copy: the interface takes Helvetica Neue from the reader’s own machine if it has one (a Mac does), and otherwise Helvetica or Arial’s stand-ins, so it looks different on Linux and Windows. Matthew Hammer asked, on 2026-11-19, for an open font Hazel can ship with itself, so the interface looks the same everywhere: a choice for the team. This page lays out 11 candidates, all under the SIL Open Font License 1.1, side by side in pieces of Hazel’s interface, measured against Helvetica Neue.

Outline#

  1. The candidates, side by side: each font drawing the same pieces of Hazel’s interface, with your own text if you like.
  2. How each measures against Helvetica Neue: the width it sets Hazel’s words at, its x-height, and its files’ size.
  3. Our lean: Inter; Roboto for the least change; Source Sans 3 to match the code font.
  4. What adopting one takes: two files, two rules, one variable, and the license.
  5. What next, and how this was put together.

The candidates, side by side#

Each card draws the same pieces of Hazel’s interface in one font: a right-click menu, a panel’s heading and text, a type error, two buttons and a line of numbers, with a line of code in Source Code Pro, Hazel’s code font, under them. The first card is what Hazel showed until #2837: Helvetica Neue, here only if your machine has it. Each candidate loads from Fontsource under a name of its own, so a copy installed on your machine is never used instead.

How each measures against Helvetica Neue#

IBM Plex Sans, Roboto and Arimo set Hazel’s interface words within 2% of Helvetica Neue’s width, with x-heights within 2% of its own; Inter sets them 5% wider and looks about 6% larger. Every candidate’s regular and bold, for the Latin alphabet, are 22 to 67 KB together, where Helvetica Neue’s two files were 258 KB. Width decides whether a label still fits where it fit; x-height, the height of small letters, decides how large text looks at the same size.

Width is the advance widths of a sample of Hazel’s interface words (menu items, panel names, an error message), summed; x-height and cap height are the fonts’ own (OS/2 table); all three against Helvetica Neue’s, so 1.00 is the same. The sizes are Fontsource’s Latin files, enough for Hazel’s English interface; a whole font, with other alphabets, is larger.

Our lean#

Inter: a neutral grotesque in Helvetica’s line, designed for screens and interfaces, and among the most used open fonts for them; its cost is text about 5% wider, so a tight label or button may need a look. Three others, each for a reason the team may weigh more:

  • Roboto, for the least change. Neutral, and within 2% of Helvetica Neue in width and x-height: the interface would look much as it does on a Mac today, everywhere.
  • Source Sans 3, to match the code font. It is Adobe’s companion to Source Code Pro, by the same designer; it runs small (0.92 wide, 0.94 tall), so Hazel would raise its size about 6%.
  • Atkinson Hyperlegible, for legibility. Designed for readers with low vision, its letters harder to confuse (I, l, 1; O, 0); a choice that says something about who Hazel is for.

The choice is the team’s, and the cards are the way to make it: the numbers say what will shift, not what reads well.

What adopting one takes#

Four small changes on top of #2837, in one pull request.

  1. The font’s two files (regular and bold), in src/web/www/style/fonts/: Fontsource’s Latin .woff2, or the font’s own release, for more alphabets.
  2. Two @font-face rules in style/fonts.css, as Source Code Pro has.
  3. The variable, in style/variables.css: for Inter, --ui-font: "Inter", "Helvetica Neue", Helvetica, Arial, sans-serif, so a page that cannot load the file still falls back as it does now.
  4. The licenses, in licenses/: the SIL Open Font License’s text, for the new font and for Source Code Pro, whose copy Hazel already ships without it.

hazelgrove/hazeljs, whose package now holds Hazel’s editor (hazelgrove/hazeljs#2), takes the same files with its next build.

What next#

  1. The team chooses a font, with the cards above.
  2. A pull request adds it, on top of hazelgrove/hazel#2837: the files, the rules, the variable and both licenses.
  3. hazeljs’s package and the Hazel build on fumola.org follow with their next builds.

How this was put together#

On 2026-11-19. The candidates are the sans-serif fonts on Fontsource that are common choices for interfaces, each under the SIL Open Font License 1.1 as its npm package (@fontsource/<name>) declares, at the versions in the table. 059/drivers/measure059.py fetches each one’s Latin regular and bold .woff2 from jsDelivr and reads them with fontTools: x-height and cap height from the OS/2 table, and the width of a fixed sample of Hazel’s interface words from the advance widths; Helvetica Neue’s numbers come from the file Hazel shipped until #2837, read locally and not kept here. The page loads each candidate from the same addresses. Whether your machine has Helvetica Neue is measured in the page: a line of text in Helvetica Neue and in a fallback, compared by width. The numbers are in 059/data/fonts.json.
